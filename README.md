# Interview OS

**Practice Interviews. Get Hired.**
An AI-powered mock interview platform that asks, listens, evaluates, and tells you exactly how to improve.

Interview OS runs a realistic, *adaptive* mock interview: it generates each
question live based on how you've answered so far, scores every response
across seven rubric dimensions, adjusts difficulty in real time, and ends
with a recruiter-style verdict, an improvement plan, and a downloadable PDF
report.

---

## Features

- **AI-Powered Questions** — no fixed question bank; each question is generated by the LLM based on role, interview type, and interview history.
- **Adaptive Interviews** — difficulty rises, holds, or eases based on your last score (see `utils/helpers.next_difficulty`).
- **Text answers now, voice-ready architecture** — voice input is fully wired into the UI behind a feature flag; plug in a speech-to-text provider to turn it on.
- **Real-Time Evaluation** — technical accuracy, relevance, completeness, communication, confidence, problem solving, and structure, each 0–100.
- **Interview Analytics** — category breakdown + a per-question score trend chart.
- **Downloadable PDF Report** — a professional, recruiter-style performance report (ReportLab).
- **Dashboard & History** — average/best score, strongest/weakest skill, and a "My Interviews" list with a full report view for any past session.

## Architecture

```
interview-os/
├── app.py                        # Streamlit entry point + routing + theme
├── components/
│   ├── avatar/AIInterviewerAvatar.py   # Isolated interviewer presentation
│   ├── interview/{setup,interview_ui,results}.py
│   └── dashboard/dashboard.py
├── services/
│   ├── ai_interviewer.py         # Single point of contact with the LLM
│   ├── question_engine.py        # Generates one question at a time
│   ├── evaluator.py              # Scores each answer against the rubric
│   ├── interview_engine.py       # Orchestrates the adaptive loop + summary
│   ├── speech_to_text.py         # Voice input, feature-flagged
│   └── report_generator.py       # PDF report (ReportLab)
├── database/
│   ├── models.py                 # SQLAlchemy: User, Interview, Question, Answer, Evaluation
│   └── database.py               # Engine/session + repository helpers
└── utils/
    ├── config.py                 # All env vars read here, nowhere else
    └── helpers.py                # Formatting, JSON parsing, difficulty rule
```

UI code never talks to the LLM or the database directly — it goes through
`services/interview_engine.py` and `database/database.py`. This keeps the
adaptive logic and scoring rubric in one place and testable without
Streamlit.

### Why the avatar is a separate component

`components/avatar/AIInterviewerAvatar.py` renders a static avatar today,
but it's built as the seam for the next stage: a talking, lip-synced
interviewer. The interview loop only ever sets a `speaking_state`
(`IDLE` / `THINKING` / `SPEAKING` / `LISTENING`) and `current_text` — it has
no idea how those get rendered. Adding TTS + a talking avatar later means
wiring:

```
LLM response → Text-to-Speech → Avatar speaking animation → candidate
```

entirely inside this one file, without touching `interview_engine.py` or
`interview_ui.py`.

## Tech Stack

Python 3.11+, Streamlit, FastAPI-ready service layer, Anthropic (Claude) for
interviewer intelligence, SQLAlchemy (SQLite by default, PostgreSQL/Supabase
via `DATABASE_URL`), ReportLab for PDF generation, Plotly for analytics.

## Installation

```bash
git clone <your-repo-url>
cd interview-os
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

## Environment Variables

Set these in `.env` (never commit real values — `.env` should stay in
`.gitignore`):

| Variable | Required | Description |
|---|---|---|
| `ANTHROPIC_API_KEY` | Yes, for live interviews | Powers question generation, evaluation, and the final verdict |
| `ANTHROPIC_MODEL` | No | Defaults to `claude-sonnet-4-6` |
| `DATABASE_URL` | No | Defaults to local SQLite; set to a Postgres/Supabase URL for production |
| `SESSION_SECRET` | Recommended | Used for session handling |
| `SPEECH_TO_TEXT_PROVIDER` | No | Leave unset to keep voice mode off; see roadmap |

Without `ANTHROPIC_API_KEY`, the app still runs — the landing page,
dashboard, and history all work — but starting a new interview will show a
clear "AI interviewer unavailable" message instead of crashing.

## Local Development

```bash
streamlit run app.py
```

The app creates a local SQLite file (`interview_os.db`) on first run.

## Cloud Deployment

The app is deployment-target agnostic:

- **Streamlit Community Cloud** — point it at `app.py`, add your secrets in the dashboard's "Secrets" panel (same keys as `.env`).
- **Any container platform** (Render, Railway, Fly.io, etc.) — `pip install -r requirements.txt && streamlit run app.py --server.port $PORT --server.address 0.0.0.0`.
- **Database** — swap `DATABASE_URL` to your Supabase/Postgres connection string; no code changes needed since the models use plain SQLAlchemy types.

## Example Interview Flow

1. Candidate picks **Python Developer / Fresher / Technical / Medium / 5 questions**.
2. AI asks a Medium Python fundamentals question.
3. Candidate answers → scored 82/100 → AI: *"Good explanation. Let's go one level deeper."* → next question is Hard.
4. Candidate struggles on the Hard question → scored 48/100 → AI: *"That's okay, let's approach this from a simpler angle."* → next question drops to Easy/fundamentals.
5. After 5 questions: overall score, category breakdown, AI verdict, readiness bucket, improvement plan, score trend chart, and a downloadable PDF.

## Development Roadmap

**MVP (done):** landing page → setup → adaptive AI questions → text answers → real-time evaluation → adaptive difficulty → final score/analytics → PDF report → interview history/dashboard.

**Next stages (spec sections 12–17), built without breaking the MVP:**
1. Voice input — implement `services/speech_to_text.py::transcribe()` against a real provider (e.g. Whisper API) and set `SPEECH_TO_TEXT_PROVIDER`.
2. Text-to-speech for the interviewer's questions.
3. Talking `AIInterviewerAvatar` (swap the static render for a video/canvas element; state machine is already in place).
4. Lip-sync driven by the TTS audio.
5. Webcam-based candidate presence/engagement signals.
6. Fully real-time (streaming) interview mode.

At every stage the app should remain fully usable in text-only mode.
